## 局域网实际 ESP32 HTTPS

设备连接用户指定的 2.4GHz Wi-Fi。使用独立合成数据与随机测试 token，运行与生产相同的 HTTP handler，未使用车辆数据或生产 token。默认启用证书验证。

初次仅含 IP SAN 的证书被固件拒绝（mbedTLS -9984）。确认设备 UTC 时间正常后，测试证书改为同时含 IP SAN 和 DNS SAN（值均为同一 LAN IP），设备成功通过 TLS 并接收数据。没有调用 setInsecure 或降低验证要求。部署脚本已加入双 SAN，但服务器已存在证书不会自动重签，因此远端仍待更新。

`smoke-api.py --reconnect` 完整通过：断网时保留缓存、隐藏速度，Home 仍可操作，约 30 秒后重连并恢复 HTTPS 数据；采样串口响应最大 439ms（含重试与传输，并非屏幕帧时延）。

已验证正常/充电响应、超过 60 秒数据隐藏速度、非法字段不覆盖有效缓存、503/慢响应保留缓存并隐藏速度、后续正常响应恢复。网络任务栈剩余观测约 7KB，TLS 期间最低可用堆约 217KB；这只是短时观测，不等价于长时间无泄漏证明。

串口脚本最初受异步日志拼接及旧状态响应影响误报，已改为识别完整状态行、清理旧接收数据并等待目标状态。实体触摸与按键没有由串口测试替代。

## USB 切换稳定性

最终固件的一次 100 轮测试在至少 75 轮后出现 macOS 串口 `Device not configured`，USB 端口随后重新枚举；未捕获 panic，原因尚未确定，不能判为完整通过。重新打开串口后的启动原因是 USB_UART_CHIP_RESET，但打开串口本身也会复位，因此它不能证明此前断开的原因。

重新运行最终脚本后，100 轮切换完整通过：Launcher 空闲不重绘、Mock 更新/充电、全部页面与返回行为正常；heap 前后均 266,272 字节，min heap 前后均 265,328 字节。此结果不消除前一次 USB 瞬断的未知原因，仍需更长时间与线缆/供电验证。
